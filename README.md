# ReXNative

**A native Direct3D 12 renderer for Xbox 360 games recompiled with the ReXGlue SDK, with
DLAA, DLSS and DLSS 5, and a tool that adapts it to a new game by itself.**

## What it is

A [ReXGlue](https://github.com/rexglue/rexglue-sdk) port runs a game's own PowerPC code
recompiled to x64, and draws through an emulation of the Xbox 360 GPU (Xenos): command buffers,
EDRAM, resolves. ReXNative replaces that drawing with a renderer of its own. It hooks the game's
calls into the XDK's Direct3D library (draws, clears, resolves, Swap), reads the state the guest
D3D device keeps, and draws each call with D3D12 directly. No EDRAM emulation, and room for what
the console never had:

- **NVIDIA DLAA, DLSS Super Resolution and DLSS 5** neural rendering, or AMD FSR, on the 3D scene;
- MSAA up to 8x, anisotropic filtering, FSR 1 screen scaling, frame generation, HDR10 output;
- frame pacing on the display, and a **settings HUD** over the running game (F1, or Back + Start
  on a pad) that saves into the game's configuration file;
- runs on Windows and on the Steam Deck (under Proton, through vkd3d-proton).

The renderer comes from [pgr4-native](https://github.com/shaunsingh/pgr4-native) (Project Gotham
Racing 4) and was ported by hand to From Dust
([FromDustDeck](https://github.com/gtguerreiro-max/FromDustDeck)) and Iron Brigade. ReXNative is
that renderer made **universal**: one `src/native` for every game, and everything that differs
between games generated by a tool.

## How it adapts to a game

What changes from game to game is small:

| What | How ReXNative finds it |
|---|---|
| The addresses of the XDK D3D functions it hooks (Swap, Draw*, Clear, Resolve, push-buffer segments, shader load, ~100 more for tracing) | matches the game's ReXGlue-generated code against a known port's |
| The offsets of the guest D3D device's fields | votes from the aligned instructions of the matched functions |
| Which Resolve function to hook and where its arguments are (LTCG builds inline the wrapper and drop arguments) | follows each argument's uses in both listings |
| Resolve's default clear colour | its code pattern: one float (XDK 6132) or a 16-byte vector (XDK 20353) |
| The scene surface DLSS works on | at run time, from one frame's resolves (`rexnative scene`) |
| Engine behaviour (a second D3D device, cvar defaults) | your choice, in `overrides.json` |

The tool writes all of it into a header, `game_layer.h`, and a list of hooks, `d3d_surface.inc`.
The renderer reads nothing else about the game.

The matching works on the C++ that ReXGlue generates (every PowerPC instruction is kept there as
a comment), so it needs no disassembler. For each function of a reference port it tries, in order
of confidence: the same listing; the same with every number masked; the only such one inside the
D3D library; the function a matched one calls at the same place (the XREF idea of Cxbx-Reloaded's
XbSymbolDatabase); the neighbour of a matched one (the library keeps its object files' order);
the one that calls the same matched functions; a similar listing; and a public wrapper the
compiler inlined away. The reference is chosen from the game's `default.xex`: the same D3D
library version first, then LTCG or not, then the closest XDK build; the other references fill
gaps and cross-check.

## Status

| Game | XDK D3D | With this renderer |
|---|---|---|
| Project Gotham Racing 4 | D3D9 2.0.6132 | the renderer's origin: the whole game ([pgr4-native](https://github.com/shaunsingh/pgr4-native)) |
| From Dust | D3D9 2.0.20353 | **built from ReXNative**: plays (menus, levels, HUD), as with its hand-made copy ([FromDustDeck](https://github.com/gtguerreiro-max/FromDustDeck)) |
| Iron Brigade | D3D9LTCG 2.0.20353 | **built from ReXNative**: title screens, HUD, the intro and its video, the first mission with its scenery (its GPU hang came from draw arguments its LTCG build moves, now remapped; the video is a Scaleform bitmap drawn with DrawIndexedVerticesUP, hooked since 2026-11-15, into a gamma render target; the static scenery is in recorded command buffers, replayed since 2026-11-15); plays on the Steam Deck under Proton at its 30 FPS |

From Dust and Iron Brigade now build their renderer from this repository (`rexnative_add()`
and a generated `game_layer.h`), with no copy of their own: tested on a PC, each draws what its
hand-made copy drew. PGR4 still has its own copy in pgr4-native.

### Validation

Each port's layer was regenerated without using that port, and compared with the one made by
hand (`python -m rexnative validate <port>`):

| | Hooks | Device offsets | Hook list (`d3d_surface.inc`) |
|---|---|---|---|
| Iron Brigade from From Dust | 24 of 25 the same, +1 found | 30 of 30 | 82 of 83, +4 |
| From Dust from PGR4 (another XDK) | 24 of 25 the same | 30 of 30 (11 had moved) | 104 of 104, +37 |

The differences were, on inspection, mostly mistakes in the hand-made layers. Iron Brigade
passed 0 for Resolve's `slice` argument, which its inner Resolve does read. Its hook list had one
false match. From Dust read PGR4's default clear colour address. From Dust's scene surface was
still PGR4's, so the upscaler never saw its scene. The `slice` and the clear colour are now
fixed in the ports' sources.
The one hook the tool did not find in From Dust was inlined by the game; the one it added to
Iron Brigade is its CreateDevice.

## Using it

Requirements: Python 3.10+ (the tool has no dependencies); for the renderer, Windows with Visual
Studio 2022 (or its Build Tools) with the C++ workload and its Clang tools, git, CMake and
Ninja, and the NVIDIA DLSS SDK and DLSS 5 headers (from NVIDIA). The ReXGlue SDK the renderer
needs (pinned, with its patches: [sdk/README.md](sdk/README.md)) and the AMD FidelityFX SDK
v2.3.0 come from one script:

```powershell
scripts\build-sdk.ps1
```

**1. Generate the game's layer.** The game's ReXGlue `generated/default` directory and its
`default.xex`, against the known ports listed in `ports.json` (copy `ports.example.json` and set
your paths: each reference needs its port's sources and generated code):

```bash
python -m rexnative adapt --generated path/to/game/generated/default --xex path/to/game/default.xex --name mygame --title "My Game" --out results/mygame
```

`results/mygame/report.md` lists what was found, how, how sure, and what to check. Reports
and messages are in English; `--lang pt` (or `REXNATIVE_LANG=pt`) writes them in Portuguese.

**2. Add the renderer to the game's build:**

```cmake
include(path/to/ReXNative/renderer/rexnative.cmake)
rexnative_add(mygame
    LAYER_DIR       ${CMAKE_CURRENT_SOURCE_DIR}/results/mygame
    REXGLUE_SDK_SRC path/to/rexglue-sdk
    FIDELITYFX_SDK  path/to/FidelityFX-SDK
    DLSS_SDK        path/to/DLSS
    DLSS_NR         path/to/dlss_nr)
```

and in the game's app call `rexnative::hud::SetConfigPath`, `Initialize` and `Shutdown`
(`renderer/src/hud/hud.h`). ReXNative then draws the game by default (the layer's
`kDefaultEnabled`); `--rexnative=false` hands it back to ReXGlue's Xenos plugin. Every option
is a `rexnative_*` cvar; the names from PGR4Native (`pgr4_native_*`, `pgr4_d3d_*`) still work
and log their new name.

**3. Measure the scene for DLSS.** Run with `--rexnative_resolve_dump=<dir>`, create
`<dir>/dump.request` in a 3D scene, then:

```bash
python -m rexnative scene dir/f1234-resolves.jsonl
```

and put the result in `results/mygame/overrides.json`; `adapt` again.

Other commands: `rexnative info <xex>` (title, XDK libraries), `rexnative validate <port>`,
`rexnative extract` (the known ports' layers), `rexnative neutral` (import a port's renderer
changes into `renderer/`), and `python -m rexnative.checkneutral` (compile `renderer/` against a
layer with a game build's flags). [docs/GAME_LAYER.md](docs/GAME_LAYER.md) describes the layer.

### Debugging a game

Starting a game for every experiment costs minutes (logos, intro, menus). Instead:

- `scripts\live.ps1 start -Dir <game dir> -Exe <exe> -Route "<keys>"` starts it once in a
  1280x720 window and drives it to the problem; then each experiment takes seconds on the
  running game: `shot` (window capture), `debug "<mask>"` (the renderer's switches: depth,
  stencil, cull, blend, alpha test off, skip a range of draws), `snap` (render targets after
  given shaders; `python scripts\snaps.py` turns them into images), `drawlog` (one frame's
  draws), `trace` (the guest push buffer of one frame), `log`, `stop`. Only a rebuild needs a
  new start.
- With `start -RenderDoc` (RenderDoc's folder in `REXNATIVE_RENDERDOC`), `capture` takes a
  RenderDoc capture of the next frame, and `scripts\rdoc.ps1` queries it with the game closed:
  `actions` (every draw, its index count and targets), `history -X -Y` (pixel history: which
  draws touched a pixel and what failed), `inputs -Event` (a draw's textures as PNG), `save`,
  `buffer -Offset -Size` (bytes of the renderer's copy of guest memory, to compare with the
  game's).

Iron Brigade's static scenery (2026-11-15): the pixel history showed no G-buffer draw on a
building whose depth was there; its mesh was drawn only in the shadow and depth passes, and the
push-buffer trace showed two large INDIRECT_BUFFERs into ordinary memory: recorded command
buffers (RunCommandBuffer), whose draws no hook saw. They are replayed now (roadmap 9).

## Layout

```
renderer/src/native/           the renderer (same for every game)
renderer/src/rexnative_d3d_hooks.cpp   the guest D3D hooks and frame trace
renderer/src/hud/              the settings HUD
renderer/src/glue_defaults.cpp game-side functions, for a game with nothing special
renderer/rexnative.cmake       rexnative_add()
sdk/                           the ReXGlue SDK the renderer needs: lock and patches
scripts/build-sdk.ps1          fetch, patch, build and install that SDK
scripts/live.ps1, snaps.py     a running game for experiments, snapshots as images
scripts/rdoc.ps1, rdoc.py      RenderDoc capture queries (draws, pixel history, textures)
rexnative/                     the adapter (python -m rexnative)
docs/GAME_LAYER.md             what game_layer.h holds
```

## Roadmap

Improving it a little at a time:

1. ~~Build From Dust and Iron Brigade from `renderer/` + their generated layers, and check them
   in game.~~ Done (2026-11-14).
2. Find the scene surface at run time, so DLSS works without measuring it.
3. Find the HDR pass before the game's tone mapping, for DLSS 5.
4. ~~Rename the `pgr4_native_*` options and the `pgr4::native` namespace (keeping the old names
   working).~~ Done: `rexnative`, `rexnative_*`; ReXNative is on by default.
5. ~~Ship the SDK patch set the renderer needs, pinned, with a build script.~~ Done
   (`sdk/`, `scripts/build-sdk.ps1`); still to do: build a game end to end from it on a clean
   machine.
6. Every new port becomes a reference and makes the next one easier: games on the same XDK
   build match best.
7. ~~The tool's reports and messages are in Portuguese for now; English output.~~ Done:
   English by default, `--lang pt` for Portuguese.
8. Memexport draws (shaders that write to memory). They run (2026-11-15) with shared memory as
   a UAV (`--rexnative_memexport`), their pages stay the GPU's until the CPU writes them, and
   what they changed is written back into guest memory before a texture over it is read and at
   the Swap (`--rexnative_memexport_readback`, a wait for the GPU; Xenia Canary's snapshot and
   diff). Iron Brigade's black intro video turned out not to be one of them: Scaleform draws the
   decoded frame with DrawIndexedVerticesUP (inline vertices and indices, which no hook saw;
   the tool now finds BeginIndexedVertices next to DrawVerticesUP), into a `k_8_8_8_8_GAMMA`
   target the renderer wrote linear, half as bright (now in the console's gamma,
   `--rexnative_gamma_targets`; a draw that blends into one goes through an sRGB view, so it
   blends in linear color as the console does). Still to do: a game whose picture needs
   memexport, and avoiding the wait when nothing on the CPU needs it.
9. ~~Recorded command buffers (RunCommandBuffer).~~ Done (2026-11-15). Iron Brigade records
   its static scenery's G-buffer draws on a second device and runs them each frame through
   INDIRECT_BUFFER packets, which no hook saw, so that scenery showed the previous passes' data
   (yellow). RunCommandBuffer is now hooked (overrides.json `functions.RunCommandBuffer`), and
   `renderer/src/native/cmd_replay.cpp` reads the object's chunk list and walks its PM4: register
   writes, constants, shader loads, predication, and DRAW_INDX packets as native draws, with the
   state the call inherits and keeps as the GPU has it. A buffer is checked whole before anything
   is applied. In Iron Brigade's first mission that is 2 buffers and 343 draws a frame, about
   0.5 ms of decoding. `--rexnative_cmdbuf` 0 off, 1 count and log, 2 replay (the layer's
   `kDefaultCmdBuf`); `--rexnative_d3d_control` takes `cmdbuf 0|1|2`, `cmdbuf log N` and
   `cmdbuf dump [tag]` (each packet of the next two buffers into the trace folder);
   draw-debug.txt bits 4096 and 8192 skip the replayed draws or all others.

No game files, generated code or data from the games are in this repository: you need your own
copy of each game and its ReXGlue project.
